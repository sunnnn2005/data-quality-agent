# Code of Conduct

Data Quality Agent is a small public project for learning, review, and reproducible data-quality tooling. Everyone participating in issues, pull requests, reviews, or discussions is expected to keep the space respectful and useful.

## Expected Behavior

- Be respectful when giving or receiving feedback.
- Keep reviews focused on the project, code, documentation, reproducibility, and data-quality workflows.
- Share only public, redacted, non-sensitive information.
- Do not post private data, customer records, credentials, raw production rows, or personal contact information.
- Assume mistakes can be fixed through clear evidence, tests, and focused discussion.
- Help new contributors understand the smallest useful next step.

## Unacceptable Behavior

- Harassment, insults, threats, or personal attacks.
- Posting private business data, secrets, customer records, raw production rows, credentials, or personal contact information.
- Misrepresenting usage, feedback, stars, adoption, employment status, or reviewer identity.
- Spamming issues, pull requests, or review forms.
- Pressuring people to provide fake stars, fake feedback, or unverifiable endorsements.

## Reporting

If something in this project feels unsafe or inappropriate, open a GitHub issue only if it can be discussed publicly without private information. For sensitive security concerns, follow [SECURITY.md](SECURITY.md).

Project maintainers may edit, hide, or close issues and pull requests that include private data, spam, harassment, or unverifiable outcome claims.

## Outcome Evidence Boundary

Public feedback, users, business-case validation, and GitHub stars should only be counted from verifiable public evidence. Do not inflate metrics, submit fake reviews, or ask others to trade engagement.
